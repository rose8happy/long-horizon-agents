# 恢复演练与有效性检查

先在一个小型真实项目里验证，再增加平台适配和功能。下列是验收场景，按实际风险选择；不是每次任务都必须重复执行的仪式。

## 恢复场景

| 场景 | 应有行为 |
| --- | --- |
| 全新会话接手 | 从 MISSION、PLAN、CURRENT 找到目标、实际阶段和下一动作，相关历史按需读取 |
| 同一唤醒重复运行 | 识别已有任务或终态，不重复发车 |
| 错过预计唤醒 | 下一轮根据实际运行与产物接续，过时 ETA 不覆盖真实状态 |
| SSH 或服务不可达 | 单独记录连接阻断，不把它解释为任务失败 |
| 进程退出 | 核实际退出状态与必要产物，失败保留成本；进程消失不等于成功 |
| 新计划到来 | 运行任务保持原合同，在安全边界采用新版本 |
| 并行角色编辑 | 各自维护负责文件，通过证据链接与 PLAN 交接 |
| 用户停止 | 分辨停止唤醒、停止计算或停止整体项目，按请求执行 |
| 方向产生负结果 | 如实记录，保留证据，选择下一有价值任务 |
| 数据归集 | 有价值小记录在运行期间已接收，稳定成果有可复用位置 |

## 安装与初始化检查

自动测试覆盖：原生 discovery 目录安装、自包含包脱离原始仓库运行、安装冲突与已有修改保留，以及项目首次创建、重复运行、已有 AGENTS 保留、dry-run、异常路径与标记。测试只使用临时目录，不调用模型、scheduled task 或远程资源。

```sh
python -m unittest discover -s tests -v
```

## 项目层效果

观察一个完整任务周期，比较接入前后的实际工作：

- 用户需要催促和纠正的次数。
- 从真实资源释放到下一项就绪任务发车的等待时间。
- 重复启动、无效重跑与重复读取的成本。
- 换会话后恢复正确工作的耗时与错误。
- 核心交付的完成速度与质量，重要负结果是否被保留。
- 模型、工具和计算资源的实际用量。

记录观察区间与样本范围，先形成经验结论；不要为了评价 agent 配置重跑昂贵实验。两个角色带来的收益应超过额外审查和交接成本，小任务可以只用一个执行者。
