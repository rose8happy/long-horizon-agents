# 在 Codex 中使用

通过原生 `$long-horizon-agents` skill 加载框架。安装脚本复制自包含 skill，项目初始化器创建持久文档；agent 加载后根据用户目标实际接入、执行与接续。模型、权限、会话和 scheduled task 使用宿主的实际能力。

## 工作区与会话

1. 让 agent 使用 `$long-horizon-agents` 接入 canonical 工作区。已有项目先读取 `.agent/PROJECT.md` 映射并复用原记录；新项目由 agent 初始化并从用户请求整理目标与授权。
2. 两个已分配的规划者、执行者会话读取同一份项目文档。只有一个会话时可临时兼任；需要创建另一个持久会话时依用户明确请求和平台能力操作。
3. 通过客户端选择模型与推理强度。`agent.config.example.toml` 不会自动切换模型。模型不可用时说明限制并选择用户接受的替代配置。
4. 向会话发送“使用 `$long-horizon-agents` 作为规划者 / 执行者继续项目”。首轮即开始实际交付；后续从项目 `AGENTS.md` 和紧凑状态恢复。
5. 用户授权双向协作后，记录两个真实会话 ID、宿主入口和授权范围。已有授权直接复用；安装模板或配置开关本身不是授权。

远程项目使用同一个远端仓库和访问入口。临时 worktree 适合隔离代码实现；共享进度仍需一个可访问的 canonical 位置，避免两个角色各维护一套状态。

## 两个唤醒

| 角色 | 适合的时机 | 提示模板 |
| --- | --- | --- |
| 规划者 | 关键结果、重要冲突、持续阻断与低频总览 | `planner-wake.md` |
| 执行者 | 下一依赖信号的预计终点，必要时一次中点或 ETA 校准 | `executor-wake.md` |

让客户端在对应会话中创建 scheduled task，并使用模板内容。每个角色只维护自己的既有唤醒，不修改另一个角色或其他项目的任务。

示例请求：

> 在这个规划者会话中建立一个低频项目审查 scheduled task，使用 `.agent/codex/planner-wake.md` 的职责与文档入口；具体节奏参考项目计划。状态保存在文档中。

> 在这个执行者会话中，只在真正等待任务信号时安排下一次接续，使用 `.agent/codex/executor-wake.md`；按下一决定性信号的预计时间调整同一个 scheduled task。

这些句子是供用户或 agent 使用的请求示例。用户已授权长期接续时，agent 自主调用平台工具维护本角色唤醒；安装脚本本身没有创建任务。

## 调度与恢复

- 唤醒服务依赖调度平台；不要假定 Git clone 会自动安装或启用调度。
- 会话内 scheduled task 适合返回原会话。长程可靠性仍来自共享文档，换一个新会话也应能恢复。
- 修改计划时间时使用明确时区；Windows 跨时区接续建议用显式 UTC，同时写明用户当地时间。
- 检查平台实际显示的下一运行时间和可用持久状态。仅更新响应成功不足以证明实际时刻正确；界面不可读时照实说明。
- 本地文件任务需要电脑及桌面应用保持可用。不能据此假定远端任务也已停止。
- 计划内短链使用站点程序接续；桌面 scheduled task 观察较晚的决定性信号。
- 桌面环境的本地任务采用 ETA 唤醒。本仓库不假定平台能接收任意 GPU 作业完成事件；若需事件触发，由项目实现明确适配。
- 未能如期唤醒时，下一次启动根据实际任务状态恢复；重复唤醒也不重复发车。
- 用户要求停止或项目完成时，关闭有关唤醒。暂停唤醒与暂停计算任务是不同动作，按请求分别处理。

任务说明保持短小：职责、当前目标、文档入口、报告与停止条件即可。运行状态、PID、时间记录和成本留在 `CURRENT.md` 或任务卡。

## 权限与跨会话消息

按项目需要设置实际权限。角色提示和配置文件本身不会授予工具权限。既有授权内的常规可逆工作自主执行；超出范围的实质动作依用户和平台规则处理。

两个角色通过共享文档保留状态，并可使用实际跨会话消息工具及时协作。建立角色时可由用户一次说明：

> 允许这个项目已分配的规划者与执行者互相发消息，用于任务分配、结果反馈、问题讨论和职责交接。在项目既有授权范围内自主处理，不必每条消息再次确认。

复用已有的同等授权，不要求用户重复这句话。两个角色都应能取得直接用户授权的可信依据；单凭另一个任务请求“回复我”不代表用户已批准反向发送。

宿主提供 `send_message_to_thread` 等工具时，使用其真实参数和记录的会话标识发送，不把平台名称当作 API 保证。消息通常会唤起接收方工作，发送前确认内容有新信息或明确动作，避免重复消息与定时唤醒。不要只为发消息切换对方模型或更改其设置。

任务分配和反馈不需要逐步批准。只有资源或文档所有权转移才等待明确接受；在此之前原负责人继续负责，其他可执行工作继续推进。重要决定与责任变化写入共享文档；消息可以很短，链接相应内容即可。

没有消息工具时，将请求写在相应计划或状态中并按既有唤醒接续，说明未发送；不要伪称双方已经收到或同意。创建另一个持久会话、定时接续及项目外动作仍按用户现有授权与平台能力执行。
