# 协作、交接与恢复

本协议支持长期项目的连续推进。按项目需要裁剪，不把模板字段或流程步骤变成额外审批。

## 1. 目标与事实

用户目标、授权和明确限制保存在 MISSION。计划说明下一步，实际记录说明发生了什么。计划与事实冲突时先查原结果，修正过时状态；agent 自己的旧结论不具有用户指令的地位。

任务完成要达到其交付判据。一个局部阶段、报告或进程启动完成，不代表整体目标完成。规划者审查剩余缺口，执行者接续当前可执行工作。

## 2. 文档所有权

| 文件 | 写入负责人 | 其他角色如何贡献 |
| --- | --- | --- |
| MISSION | 用户；规划者忠实整理 | 执行者指出缺失或冲突 |
| PLAN、DECISIONS | 规划者 | 执行者在任务结果中提出证据与建议 |
| CURRENT、任务卡、HISTORY | 执行者 | 规划者在 PLAN 中提出方向与优先级 |

同一文件避免并发改写。重要决定与任务成果互相链接；历史索引不重复保存全部日志。Git 是可追溯的变更记录，项目文件是当前上下文的入口。

## 3. 最小交接

规划者发布一个新版本 PLAN：

- 改变的问题、优先级或任务范围及依据。
- 新任务的目的、依赖、交付和完成判据。
- 对在跑任务的影响及安全生效边界。

执行者在 CURRENT 与任务卡记录实际采用版本。已有任务继续原合同；到达检查点或终态后接收下一计划。执行者不需要等待规划者逐步审批常规实现和已授权恢复。

存在实质分歧时写明证据、替代解释及下一项能区分它们的工作。依据已有授权继续无争议部分。只有用户必须决定的范围或选择才询问。

## 4. 等待和调度

角色可以 WAITING，而它管理的任务仍 RUNNING。反复查看健康状态、保持 SSH 或等待工具不算一个独立交付。

每轮先服务到期信号，然后执行能推进的独立工作。没有独立工作时，写明下一信号、动作、负责人和 ETA，安排一次有意义的接续并结束本轮。

中点检查只有在可能改变动作时才有价值。对短任务使用一个终点唤醒；未知吞吐使用一次校准唤醒，然后按实际进度估算。状态不变时不通知用户。

唤醒是提醒，不能作为任务终态。分钟级、预先确定的步骤交给普通程序接续，可以减少硬件空闲。

## 5. 普通任务程序的最小职责

项目已有运行器能够满足需求时直接复用。需要新脚本时，优先实现：

- 明确输入、输出、运行身份和资源所有者。
- 防止同一任务重复启动，资源释放后接续已确定的步骤。
- 保存进度或可恢复状态，记录真实退出码。
- 终态后写结果与产物入口；失败保留日志和成本。
- 对长任务记录必要的耗时、资源和阶段摘要。

不需要为了通用性先开发分布式调度系统。本仓库没有提供生产任务运行器；具体完成事件、恢复语义和并发机制由项目实现。

## 6. 有价值的记录与归集

尽早确定中心证据位置。小型进度、资源、阶段退出与配置记录可以增量归集；稳定重产物按实际需要归档。记录最新接收时间和路径，保留失败成本。

复用已有稳定证据，不每轮计算所有大文件哈希。高价值稳定产物的最终归档可校验内容一致性；在接收成功、源无读写和删除已授权后才释放源文件。

## 7. 避免失控的限制与文档

新增检查、上限或审批必须服务具体风险或用户要求。写明适用范围和解除条件，用户已授权的动作不反复请示。

身份保护针对输入错配、输出碰撞、错误恢复等真实问题。数值差异是否影响科学结论应由适当比较判断，不自动要求逐位一致。成本记录不是默认费用准入。

历史结论注明范围、负项与未排除解释。旧方向可以因新证据重新开启；不因模板存在某个字段就生成一次低价值工作。

## 8. 发布和维护本模板

代码和模板使用可追溯提交。对行为有影响的变化更新 CHANGELOG，必要时使用 PR。大文件、凭据、私人会话和具体项目账本保留在所属项目，避免混入公共模板。

已安装项目保留自己的修改；模板更新按具体差异合并，不自动重写项目目标、限制、调度或历史。
